# Results

Sanitized summaries of the jev-control campaign rounds: `Rxx/summary.md` and `Rxx/metrics.json` (counts, ids, hashes; never raw transcripts, code or Jev payloads), written with `../measure.mjs`. Each round records the base commit, the versions in use, the fixture and oracle hashes, the session ledger lines it used and the provenance of every figure. A round without live sessions reports its live metrics as `"unmeasured"` (never reused from another round, never 0).

`T2/` is the build round: offline checks only, no live session.

`R01/` is the first live round: one Sonnet baseline session (S1) of the planned two; S2 was held back because the isolation check of S1 found ambient configuration that D28 did not anticipate (see its summary).

`R02/` is the second live round (D30-D32): two clean baselines (S1, S2) and two dev sessions (S1, S2) with the activation text of D31, ledger lines 2-5. `R01/`'s S1 is a pilot with the claude.ai connectors loaded and is not comparable for tokens; dev sessions are compared only with the clean baselines of R02.

`R03/` is the third live round: two dev sessions on S3 (ledger lines 6-7, 7/20 used). S3 has no clean baseline, so its token comparison is `unmeasured`. It found that `Skill jev:jev-control` returns the same-named command and never `SKILL.md`, and one dev session (b) ended with the mode off and the task unanswered; the fix is offline only.

`R04/` is the fourth live round: dev S2 (ledger 8) and the dev S3 regression of the R03 failure (ledger 9), 9/20 used. The R03 fix worked as an activation (`on` ran first in both sessions, the Skill tool was not used) but `SKILL.md` was unreadable in both (a `Read` outside the working directory is refused in this configuration); S3 was answered exactly, S2 was not done: the model learned the `decide` batch format by trial and error (seven invalid results), asked which task goes first, got a top score of 0.93-0.94 and stopped. The fix is offline only: `cli.mjs help [command]` / `--help` print the batch format and the search form, and the activation text names them.

`R05/` is the fifth live round: dev S4 at the default threshold (ledger 10) and dev S2 at a configured threshold of 0.90 (ledger 11, D33: `run-session.mjs launch --threshold 0.90`, the one explicit `JEV_CONTROL*` exception), 11/20 used. The helper's `incomplete` stopped S4 with `Incomplete:` on a clean tree; S2 passed the oracle in the order rename, greeting, test, but the changelog edit was outside the plan and `/jev:jev-done` never ran. Both models used `help decide`. The defect: every S4 `decide` was chained with `; rm -f` (not a genuine helper call, so the audit saw no decision), a Write to `/tmp` was refused, and the measurer counted scratch writes of the batch file as edits (S2: 10 edits, 1 action while blocked); `help decide`, `SKILL.md` and the examples now ask for a new file in the working directory (never an existing one; only that file is deleted) and a lone `decide`, and `measure.mjs` exempts a batch file only when the transcript proves it (created by a confirmed Write, read by a genuine `decide --file` bound at its start to that very version with a successful selected or ordered result naming only its options, nothing of unknown effects in between, and finally removed by a lone `rm`); on the R05 transcripts that proof never holds, so the corrected measurer reports the same numbers as at launch. The effect of the change is unmeasured.

`R06/` is the sixth live round: dev S1 at the default threshold (ledger 12) and the dev S2 regression at the configured 0.90 (ledger 13, D34: the second use of `run-session.mjs launch --threshold 0.90`), 13/20 used, 7 left. S1 passed the oracle but the model ran `on` together with its own search, decided nothing (no `decide`, `search` or `/jev:jev-done`; the same as R02 dev S1). S2 failed the oracle honestly: the R05 help worked in part (all 10 `decide` calls ran alone, only the plan items `rename` 0.96 and `greeting` 0.93 were executed, and the model stopped with `Incomplete:` when the last two tasks scored 0.84), but it wrote six batch files and removed none, left them in the tree and said so. Delegation was not chosen (`unmeasured`). The defect (chosen with `jev_decide`, 0.95): scratch batch files left behind; a `decide` result that ends a batch now carries a `cleanup` line naming the file for a lone `rm -f`. The effect is unmeasured; the S1 bypass, the missing `/jev:jev-done` and a scratch-repair edit counted as a blocked action are open.

`R07/` is the seventh round and has NO live session (ledger stays 13/20): an offline change so the completion gate is reachable in headless sessions (D37, D38): `done --claims jev-claims*.json` consumes a claims file written in the repository root (read, checked, removed before the snapshot, with `claims_removed` and `claims_sha256` in the result), with `help done`, a measurer exemption that needs a transcript proof, and the council's fixes (a case-insensitive file system, checks validated before the removal, a later `is_error` adjustment (the plan refused it) that exempts only complete, coherent not-accepted reports). By the user's D39 its two planned gate sessions (dev S1 at 0.95, dev S2 at 0.90 via `launch --threshold`, D36) ran in R08 (exactly two sessions, which are also R08's regression and token comparison) and are reported in `results/R08` as «R07 gate sessions (run in R08 per D39)»; an earlier orchestrator proposal of «up to 4 sessions» was withdrawn and never was a user answer (D41). Every live metric of R07 is `"unmeasured"`.

`R08/` is the eighth round and the two live sessions of the user's D39 on `86e8497`: dev S1 at 0.95 (ledger 14) and dev S2 at 0.90 through `launch --threshold` (ledger 15); they are at once the R07 gate sessions and R08's regression and token comparison, reported under «R07 gate sessions (run in R08 per D39)». Result: the live completion gate was NOT exercised (S1 edited and answered with no `decide`, `search` or `done`, as in ledger 4 and 12; S2 stopped `incomplete` at a top score of exactly 0.90 and edited nothing); the R06 `cleanup` line was followed live (both scratch files removed). Offline defect (chosen with `jev_decide`): `measure.mjs` counted the scratch batch files of a decision the helper did not clear, and the `rm` of the `cleanup` line, as edits and actions while blocked; a version the helper's own `expand`, `ask_user`, `incomplete`, `invalid` or `refused` error result read is now helper input, but only in a form the helper prints after reading the file (the OFF and denylist refusals and usage errors prove no read; council fix) (S2 recalculated: 4 batch files and 1 removal instead of 0 and 0; the 14 other historical sessions are unchanged). D41: the old «up to 4 sessions» D39 was a withdrawn orchestrator proposal, corrected in R07's files and `evaluation.md`. Ledger 15/20, 5 left (R10 2 sealed, 3 reserve).

`R09/` is the ninth round and has NO live session (ledger stays 15/20; 5 left: R10 2 sealed, 3 reserve): three offline fixes under the user's D42-D47. The skill is renamed `jev-control-mode` (the command keeps `/jev:jev-control`, so the `Skill` tool no longer returns the command text), the hook's activation text, the text after a compaction and the `on` output carry the compact protocol themselves (`rules.mjs`, within 1500 bytes; the per-prompt reminder stays under 400), and the campaign runner allows exactly one more permission, a `Read` rule for the skill directory (no `--add-dir`). `measure.mjs` keeps a confirmed Read of an exact protocol file outside the coverage denominator (D47) and reports Skill calls and skill Reads in a `skill` section (`load` is `identity_observed`, `unknown`, `refused` or `not_attempted`; the whole-skill delivery is never inferred, `full_load` stays `unknown`; the totals count every event and the free text is redacted); in the 15 historical transcripts no Skill call and no Read of the new name or directory was identified (not proof that no skill was ever loaded: the new auditor does not recognize attempts on the old path), and every other field is unchanged. The ratification round 1 of R09 corrected the rules (rule 3 asks that the headless final message START with `Incomplete:`) and the measurer's load semantics; its first commit's figures are replaced in `R09/`. Every live metric of R09 is `"unmeasured"`; R10 observes whether the rule is granted, whether the skill loads and what the rules change (n=1, no causal claim).

`R10/` is the tenth and last round: the two sealed finals F1 and F2 (ledger 16 and 17, 17/20 used, the 3 reserve sessions unused) on the frozen R09 product `6b18815` (D48), run once each in that order at the default threshold with the exact dev prompt (D49), plus the campaign summary. F1 (answer) passed its oracle: skill loaded, `on`, one `search` at 0.98, a correct answer; F2 (edit) failed its oracle honestly: `search` found no location strictly above 0.95 in two evaluations and the model stopped by asking the user, without starting the message with `Incomplete:`. Neither session used `decide`, `done` or a `Read` of a skill file; the `Skill` tool delivered the whole body as a separate meta message that the audit does not recognize (`skill.load` `unknown`, derived by hand), the Read rule is unmeasured, the live gate is still unexercised. Tokens are shown beside the baselines as different tasks without any saving (D50); the same-scenario comparison is `unmeasured`. The most important defect, chosen with `jev_decide` (0.99): a strict-threshold search stop can leave a small, fully listed repository undone. It is a recommendation for future work; the product, the measurer, the tests and the scenarios were not changed (n=1, no causal claim).
