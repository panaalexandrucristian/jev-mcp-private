# Context optimizer (on explicit request only)

**When it runs.** Only when the user asks for it in words or by command. It is never suggested, never started by a hook, never run at the end of a verification, and it is not part of the verification procedure. Without a request, do not read this file. It uses no model, no Jev call and no network: `python3 -B <skill-dir>/scripts/ctxplan.py ...` reads the active documentation (SKILL.md and the reference files that `scripts/split_manifest.json` declares) and prints Romanian text.

**Commands.**
- `ctxplan.py propose --skill-dir D [--out F]` prints at most 10 proposals (8192 bytes at most, with the number of hidden ones) and the refused operations. `--out` writes the complete machine-readable set (262144 bytes at most; a larger set is refused, never cut).
- `ctxplan.py check --skill-dir D --proposal F` proves one proposal again from the files as they are now; exit 0 `PROVEN`, exit 1 `REFUSED` with the reasons.
- `ctxplan.py usage --session F.jsonl [--session ...]` counts, for the transcripts the user named (inside `~/.claude/projects`, nothing else), the Skill calls, the reads of each reference file, the runs of each script and the errors of those calls. It prints numbers only, no text. Absence of a signal proves nothing: it never justifies removing or loosening a rule. It cannot show which rule influenced a decision.
- `ctxplan.py apply --skill-dir D --proposal F --approve PATH --snapshot SHA256 [--headless]` writes one proven reflow of ONE file, see "Applying".

**Two kinds of proposal, nothing else.**
- `reflow`: a prose line longer than 1000 characters is re-wrapped at about 160 characters. One single space becomes a newline, and inside a list item the continuation lines get the item's indent (those bytes are the only ones added, and they are counted). A break is never made inside a code span, a link, a quoted literal or a tag, never before a token that could start a block (`-`, `+`, `*`, `#`, `>`, `|`, `1.`, `---`), and never in a heading, table, quote, code fence, nested or indented line, or a line that ends with a hard break. A line it cannot classify (an unbalanced backtick or quote) is refused. The bytes do not shrink: the benefit is readability and partial reads, not measured, and it is not a saving of tokens.
- `move_block`: one whole block of the manifest moves, byte for byte, to another declared file, and a pointer line (`[block ID moved to FILE]`) stays behind. The block must not be one of `head`, `triggered`, `checklist`, `loading`, `hard-rules`, `statuses`. It is offered only when the manifest declares the loading contract: `"loading": {"needed_at": N}` on the block (the checklist step where its content is first needed) and `"opens": {"reference/FILE.md": M}` (the step by which the root has the file opened), with `M` not later than `N`. Without a declared contract the move is refused as `unknown_loading_contract`. The checker proves where the text is, not that the model will open the file: that is not provable and the output says so.

**Never offered.** Deduplication, summaries, translation, removing repetitions, shortening a pointer, changing a word or a threshold, replacing a rule by a link, and making a mandatory read optional. The strict `> 0.95` rule is stated in many places with different wording for each context; replacing the repeats by pointers is a semantic judgment that no byte comparison can prove, so it is never a proposal.

**The proof.** The unit is the byte for blocks, code and literals, and the whitespace-delimited word for prose. `AFTER` is built by the script from `BEFORE` and the operations, never read from the proposal. The inverse of `AFTER` must give every `BEFORE` file byte for byte; the words must be the same in the same order (for a move, the same multiset plus the pointer); the headings must stay; `SKILL.md` must stay within 22000 bytes. `BEFORE` is the active documentation as it stands, already proven against the frozen baseline by `split_skill.py check`; the baseline is never a source of restored text. It fails closed: a BOM, CR, non-UTF-8, symlink, undeclared file, operation of an unknown kind or snapshot that no longer matches is a refusal, and there is no warning level. Reasons: `baseline_changed`, `incomplete_manifest`, `missing_block`, `duplicate_mapping`, `protected_bytes_changed`, `non_whitespace_edit`, `markdown_ambiguous`, `unknown_loading_contract`, `loading_contract_weakened`, `unreachable_reference`, `budget_exceeded`, `unknown_operation`.

**Applying.** Only after the user approves the file by name and its snapshot hash (otherwise `not_approved`), never headless (`headless_refused`), and only a proven reflow of ONE file that needs no other file to change (the manifest included). It then uses the same path as a patch: hash check, exclusive backup `<file>.bak-<UTC>`, atomic replace, and a hash check of the result (a mismatch is reported as `final_check_failed`, never as success). Moves touch two files and are refused (`multi_file_atomic_publication_unavailable`); successive replacements are not an atomic publication. On this layout every reflow also changes the bytes of a manifest block, so `apply` refuses with `requires_manifest_change` until the manifest can record such a change. Proposals and proofs work; applying is deliberately blocked. Do not edit the files by hand to get around it.
