# Integration

## Commands and files

- `/jev:jev-control on|off|status|threshold <x>` (`commands/jev-control.md`) runs `private/jev-control/cli.mjs`; `/jev:jev-done` and `/jev:jev-locate` have explicit control branches; `agents/jev-locator.md` carries the control rules.
- Code lives only in `private/jev-control/` (`cli`, `actions`, `state`, `budget`, `client`, `contracts`, `options`, `protocol`, `search`, `done`, `receipts`, `hook`, `measure`, `run-session`, `test/`, `fixtures/`, `results/`). The upstream files (`src/`, `skills/jev`, `README.md`) are untouched.
- Edits to private jev-flow files are limited to seams: `scripts/jev-flow-hook.mjs` delegates to the control hook first; `private/jev-flow/hook.mjs` stands the flow down while the mode is on; `private/jev-flow/gate-run.mjs` and `policy.mjs` accept an optional policy (threshold, no 0.8 floor, budgeted call); `hooks/hooks.json` registers one more event, `SessionEnd`, on the same adapter. With the mode off, everything behaves as before.

## jev-flow and handoff-verify

While the mode is on for a session, jev-flow's directive, hints and Stop redirects are suppressed even with `JEV_FLOW=on`; its payload guard, state tracking and the denylist notice stay. `handoff-verify` is unchanged: its stricter obligations (strict `> 0.95`, per-file approval, never executing code from a handoff) apply on top, and its Jev calls count in the shared budget.

## Hooks (no blocking hook)

The hook is the only place that sees the real `session_id`, so it is where the session is proven. `UserPromptSubmit`: for a `/jev:jev-control` prompt, or an explicit natural-language request (the phrases of the skill description, English and Romanian, matched without case or diacritics), it creates the session's **capability** (`<session key>.<secret>`; the secret is stored 0600 in the session state, compared in constant time, never in `state.json`) and puts `Session capability: pass --session-cap <cap> to every cli.mjs call, also in subagent prompts.` into the model's context; with the mode on, an ordinary prompt starts a new request (budget counters) and prints the one-line reminder with the capability, while a mode command does not start a request. The helper accepts, in this order, an explicit `--session-id`, `CLAUDE_CODE_SESSION_ID`, or the capability; a capability that contradicts the environment's id is refused (`identity_conflict`); with none of them there is no identity and nothing is selected by guessing (a CLI of another session never adopts the most recent session). Subagents are given the capability by the parent in their prompt. A request phrased in a way the hook does not match gets no capability: the helper then refuses and the user is asked to run `/jev:jev-control on`.

`SessionStart`: after a compaction (`compact`, the same live session) the reminder and the capability are re-injected; `startup`, `resume`, `clear`, `fork` and any unknown source switch the mode **off** and rotate (remove) the capability, so nothing carries over and the mode must be requested again. `SessionEnd` (registered in `hooks/hooks.json`, any reason) switches the mode off and removes the capability. The hook runs no Jev call and no test and never blocks. State also expires after 30 days.

## What is demonstrated offline, and what is left for R02

**Demonstrated offline** (tests with hook payloads labeled as fixtures, a fake stdio MCP server, and the installed Claude Code 2.1.288 binary inspected, not run): the capability is created by the hook, proves only its own session, and is refused when wrong, foreign, malformed, expired or in conflict with the environment (`private/jev-control/test/{state,hook,cli}.test.mjs`); two sessions in one repository stay apart; a subagent process given the parent's capability shares the parent's state; `startup`/`resume`/`clear`/`fork`/unknown sources and `SessionEnd` switch the mode off and rotate the capability, `compact` keeps it; `hooks/hooks.json` registers `SessionEnd`. ## Data

Only sanitized fragments of the current repository go to Jev (`sanitize.mjs`; no `.env`, keys, credentials or tokens), and `.jev-flow-denylist` is honored: a refused repository means the mode refuses to start. No credential is read from files; the server uses the environment only, as in jev-flow.
